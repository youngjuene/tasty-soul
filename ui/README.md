# ui — 화면 전부

tasty-soul 의 인터페이스는 이 디렉토리가 전부다. 여기 밖에 화면 코드는 없다.

```
ui/
  index.html            진입 문서
  main.tsx  App.tsx     셸 — 탭 전환과 §D7 고지 게이트만 한다
  screens/              화면 7개 (§13)
  components/           차트·고지·오류 경계
  lib/                  api(백엔드 계약) · types · md · diff
  styles/               CSS 4개. 디자인 토큰은 base.css 상단
  preview/              Rust 없이 띄우는 목 — 아래 참조
  screenshots/          현재 모습
```

---

## 바로 띄우기

```bash
npm install
npm run design          # http://localhost:1421
```

**Rust 도 API 키도 Tauri 도 필요 없다.** `preview/` 가 백엔드 커맨드를 전부 가짜로
대신하므로 브라우저에서 모든 화면이 실제 데이터 모양 그대로 뜬다.

`npm run dev` 는 진짜 앱용이고 Tauri 가 없으면 화면이 죽는다. 디자인 작업에는 `design` 을 쓴다.

픽스처(`preview/fixtures.ts`)는 예쁜 값만 넣지 않았다. 일부러 아래를 섞어 두었다 —
디자인이 실제 데이터에서 깨지는지 보려면 필요하다.

- `null` 파생값 (축 2개, 타임라인 중간 2개월)
- 두 층 중 하나만 답해 2×2 셀이 정해지지 않은 항목
- 근거가 얇은 비평 (`grounded: false` → 경고가 떠야 한다)
- 한 줄짜리 서술문과 세 줄 넘어가는 서술문
- 240건 (200건 초과 → 아카이브가 점으로 그려야 한다)

## 마음껏 바꿔도 되는 것

여백, 타이포 스케일, 색, 대비, 리듬, 정렬, 모서리, 그림자, 전환, 아이콘,
빈 상태 그림, 반응형 브레이크포인트, 컴포넌트 분해, 클래스 이름 — 전부.

레이아웃도 바꿔도 된다. 지금은 모든 화면이 가운데 한 컬럼에 갇혀 있어서
넓은 화면에서 오른쪽이 크게 빈다. 아카이브만 3단이다. 손볼 여지가 많다.

## 깨면 안 되는 것

전부 이유가 있다. 예쁘게 만들려다 조용히 무너지는 것들이라 적어 둔다.

### 1. 카드의 버튼은 **정확히 2개**다

화면 2와 2.1의 답은 `○` / `×` 뿐이다. "잘 모르겠음", "일부만", "보류" 를
**추가하지 마라.** 중간 선택지를 두면 응답 대부분이 거기로 몰리고 2×2 격자가
통째로 무너진다. 판단이 어려운 항목은 **답하지 않고 카드를 넘기는 것**이 설계다.

버튼 문구도 고정이다: `그렇다` / `아니다`, `그래서 좋다` / `그것 때문은 아니다`.

### 2. `null` 은 `—` 로 그린다

파생값이 없을 때 `0`, `-`, `N/A`, 빈칸, 회색 점으로 바꾸지 마라.
`—`(em dash) 하나다. `0` 으로 보이면 "측정했더니 0" 과 구별되지 않는다.

단 **개수**는 다르다. `정정 0건` 은 진짜 0이므로 `—` 가 아니다.

### 3. 차트 라이브러리를 넣지 마라

`components/` 의 `Scatter` · `CellGrid` · `Bars` 는 전부 손으로 쓴 인라인 SVG다.
d3, recharts, chart.js, victory 등을 `package.json` 에 추가하지 마라.
패널이 3개뿐이라 의존성을 늘리지 않기로 한 결정이다. SVG 를 다시 그리는 것은 환영.

### 4. 대시보드에 어긋남 **실수 지표**를 올리지 마라

`divergence_sensory` · `divergence_cultural` 은 데이터에 있지만 화면 5는
**2×2 격자만** 둔다. 실수 두 개를 겹쳐 그리는 것보다 이산 격자가 훨씬 빨리 읽힌다.

### 5. `other_reason` 칸은 강조를 유지한다

2×2 중 "보는 것은 같으나 끌리는 이유가 다르다" 칸이다. 이 앱이 찾으려는 것이
그것이라, 네 칸을 균등하게 만들면 화면의 목적이 사라진다.

### 6. 프라이버시 문구를 줄이지 마라

- `BoundaryNotice` 의 전송 항목 표는 **행을 빼지 않는다.** "로컬 우선" 같은
  말로 뭉뚱그리지 않는다.
- 설정의 "앱은 저장한 키를 다시 읽어 보여주지 않습니다"
- 문화 층 토글의 "투입할 때마다 웹 검색이 일어납니다"
- 대시보드의 "이 이동의 일부는 취향이 아니라 프롬프트 변경에서 왔을 수 있습니다"

길다고 지우면 사용자가 모르는 채로 데이터를 내보내게 된다.

### 7. 문구는 한국어, 존재하는 문장을 유지한다

톤을 다듬는 것은 좋지만 의미를 바꾸지 마라. 특히 화면 1의
"링크를 끌어다 놓는 것은 동작하지 않습니다" 는 실제 제약이라 지우면 안 된다.

### 8. 아카이브 200건 규칙

보이는 항목이 200건 이하면 썸네일 타일, 넘으면 단색 점이다.
수천 건에서 썸네일을 전부 그리면 첫 렌더 예산(500ms)을 넘긴다.

### 9. 프런트는 계산하지 않는다

축 값, 셀 판정, 군집, 필터는 전부 백엔드가 준 값을 그대로 그린다.
화면에서 다시 계산하지 마라 — 같은 값이 두 곳에서 달라진다.
`lib/api.ts` 에 없는 것은 프런트가 할 수 없는 일이다.

## 디자인 토큰

`styles/base.css` 상단의 CSS 변수가 토큰이다. 목록과 뜻은 [`TOKENS.md`](TOKENS.md).

라이트/다크 **양쪽 다** 대응해야 한다 (`prefers-color-scheme`).
지금은 다크가 기본이고 라이트는 덜 다듬어져 있다 — 좋은 작업거리다.

---

## 확인

```bash
npx tsc --noEmit     # 타입
npm run build        # 프로덕션 번들
```

백엔드 계약(`lib/api.ts` · `lib/types.ts`)은 Rust 쪽 `src-tauri/src/commands.rs` 의
거울이다. **여기 타입을 바꾸면 Rust 도 함께 바꿔야 한다.** 화면만 손볼 거라면
그 두 파일은 건드리지 않는 편이 안전하다.
