# ui — 화면 전부

tasty-soul 의 인터페이스는 이 디렉토리가 전부다. 여기 밖에 화면 코드는 없다.

```
ui/
  index.html            진입 문서
  main.tsx  App.tsx     셸 — 탭 전환과 §D7 고지 게이트만 한다
  screens/              화면 7개 (§13)
  components/           차트·고지·오류 경계
  lib/                  api(백엔드 계약) · types(+화면에 쓰는 이름) · md · diff
  styles/               CSS 5개. 디자인 토큰은 base.css 상단
  preview/              Rust 없이 띄우는 목 — 아래 참조
  screenshots/          현재 모습
```

---

## 바로 띄우기

```bash
npm install
npm run design          # http://localhost:1421
```

**Rust 도 API 키도 Tauri 도 필요 없다.** `preview/` 가 백엔드 커맨드를 전부 가짜로
대신하므로 브라우저에서 모든 화면이 실제 데이터 모양 그대로 뜬다.

`npm run dev` 는 진짜 앱용이고 Tauri 가 없으면 화면이 죽는다. 디자인 작업에는 `design` 을 쓴다.

픽스처(`preview/fixtures.ts`)는 예쁜 값만 넣지 않았다. 일부러 아래를 섞어 두었다 —
디자인이 실제 데이터에서 깨지는지 보려면 필요하다.

- `null` 파생값 (축 2개 — 축 막대가 «아직 잴 수 없음» 을 적어야 한다)
- 두 층 중 하나만 답해 2×2 셀이 정해지지 않은 항목
- 근거가 얇은 비평 (`grounded: false` → 경고가 떠야 한다)
- 한 줄짜리 서술문과 세 줄 넘어가는 서술문
- 240건 (200건 초과 → 아카이브가 점으로 그려야 한다)

## 마음껏 바꿔도 되는 것

여백, 타이포 스케일, 색, 대비, 리듬, 정렬, 모서리, 그림자, 전환, 아이콘,
빈 상태 그림, 반응형 브레이크포인트, 컴포넌트 분해, 클래스 이름 — 전부.

레이아웃도 바꿔도 된다. 지금은 모든 화면이 가운데 한 컬럼에 갇혀 있어서
넓은 화면에서 오른쪽이 크게 빈다. 아카이브만 3단이다. 손볼 여지가 많다.

## 깨면 안 되는 것

전부 이유가 있다. 예쁘게 만들려다 조용히 무너지는 것들이라 적어 둔다.

### 1. 카드의 버튼은 **정확히 2개**다

화면 2와 2.1의 답은 `○` / `×` 뿐이다. "잘 모르겠음", "일부만", "보류" 를
**추가하지 마라.** 중간 선택지를 두면 응답 대부분이 거기로 몰리고 2×2 격자가
통째로 무너진다. 판단이 어려운 항목은 **답하지 않고 카드를 넘기는 것**이 설계다.

버튼 문구도 고정이다: `그렇다` / `아니다`, `그래서 좋다` / `그것 때문은 아니다`.

### 2. `null` 은 `—` 로 그린다

파생값이 없을 때 `0`, `-`, `N/A`, 빈칸, 회색 점으로 바꾸지 마라.
`—`(em dash) 하나다. `0` 으로 보이면 "측정했더니 0" 과 구별되지 않는다.

단 **개수**는 다르다. `정정 0건` 은 진짜 0이므로 `—` 가 아니다.

### 3. 차트 라이브러리를 넣지 마라

`components/` 의 `Scatter` · `CellGrid` · `Bars` 는 전부 손으로 쓴 인라인 SVG다.
d3, recharts, chart.js, victory 등을 `package.json` 에 추가하지 마라.
차트가 몇 개 안 되어 의존성을 늘리지 않기로 한 결정이다. SVG 를 다시 그리는 것은 환영.

### 4. 대시보드에 산점도를 되돌리지 마라

한때 `(drift, crystal)` 연결 산점도가 있었다. **뺐다.** 시간 축이 없는 평면 위의
경로라 읽으려면 아래에 시간 스트립을 따로 깔아야 했고, 그 둘을 겹쳐 읽는 것이
이 앱에서 가장 어려운 일이었다.

대시보드는 **한눈에 읽히는 자리**다. 지금 남은 둘 — 2×2 격자와 축 막대 — 은
숫자를 그대로 보여 줄 뿐 해석을 요구하지 않는다. 흩어진 것을 훑는 일은 아카이브가
맡는다. 차트를 더 얹고 싶으면 그쪽이다.

(아카이브가 그 패널을 대신하는 것은 아니다. 아카이브는 **항목**을 감각 축에
흩뿌리고, 뺀 패널은 **프로필 자체**가 달마다 움직인 자취였다. 그 자취는 지금
어디에도 없다 — 되살릴 거라면 그 사실을 알고 하라.)

### 5. 대시보드에 어긋남 **실수 지표**를 올리지 마라

`divergence_sensory` · `divergence_cultural` 은 데이터에 있지만 화면 5는
**2×2 격자만** 둔다. 실수 두 개를 겹쳐 그리는 것보다 이산 격자가 훨씬 빨리 읽힌다.

그 값들이 사는 곳은 **SOUL 화면의 `Alignment`** 다. 거기에는 격자가 없고, 바로 위에
같은 숫자를 한 줄로 적은 문서가 있어 자리를 다투지 않는다.

### 5-a. 어긋남을 실패로 그리지 마라

`Alignment` 의 첫 문장은 "높다고 나쁜 것이 아닙니다" 다. 지우거나 뒤로 밀지 마라 —
숫자를 먼저 읽으면 `0.31` 을 "31% 틀렸다"로 읽고, 그 순간 이 앱이 무엇을 하려는
물건인지 정반대로 이해하게 된다. §12.6 이 `other_reason` 을 **이 시스템이 찾으려는
것**이라고 못박은 것과 같은 이야기다. 어긋남이 0이면 배울 것이 없다.

같은 이유로 «아직 방향이라 부를 만큼은 아닙니다» 에 **경고색을 쓰지 마라.**
나쁜 상태가 아니라 아직 모르는 상태다. 문구를 아무리 조심스럽게 써도 색이 먼저
"문제 있음"이라고 말해 버린다.

### 6. `other_reason` 칸은 강조를 유지한다

2×2 중 "보는 것은 같으나 끌리는 이유가 다르다" 칸이다. 이 앱이 찾으려는 것이
그것이라, 네 칸을 균등하게 만들면 화면의 목적이 사라진다.

### 7. 프라이버시 문구를 줄이지 마라

- `BoundaryNotice` 의 전송 항목 표는 **행을 빼지 않는다.** "로컬 우선" 같은
  말로 뭉뚱그리지 않는다.
- 설정의 "앱은 저장한 키를 다시 읽어 보여주지 않습니다"
- 문화 층 토글의 "투입할 때마다 웹 검색이 일어납니다"
- 대시보드의 "이 움직임의 일부는 취향이 변한 것이 아니라 질문이 바뀐 탓일 수 있습니다" (§R11)

길다고 지우면 사용자가 모르는 채로 데이터를 내보내게 된다.

### 8. 문구는 한국어, 존재하는 문장을 유지한다

톤을 다듬는 것은 좋지만 의미를 바꾸지 마라. 특히 화면 1의
"링크를 끌어다 놓는 것은 동작하지 않습니다" 는 실제 제약이라 지우면 안 된다.

### 9. 우리말이 앞, 식별자가 뒤 — 둘 다 남긴다

`other_reason` · `surprisal` · `grain` 은 **지울 수 없는 이름**이다.
`SOUL.md` 와 MCP 와 CLI 가 그 이름으로 말하므로, 화면에서 없애면 앱 밖으로
나가는 순간 말이 끊긴다. 그렇다고 처음 열어 본 사람에게 `other_reason` 을
먼저 들이밀면 그 사람은 아무것도 읽지 못한다.

그래서 **우리말을 앞에 놓고 식별자를 옆에 작게 남긴다.**

```
이유가 다르다          ← lib/types.ts 의 CELL_LABELS · AXIS_LABELS · KIND_LABELS …
other_reason           ← .ident (base.css). 지우지 마라
```

처음에는 우리말만 읽히고, 오래 쓰면 옆에 있던 식별자가 저절로 눈에 익는다.
그때쯤 `SOUL.md` 를 열어도 낯설지 않다 — **이게 이 앱의 학습 곡선이다.**

이름 표는 전부 `lib/types.ts` 한 곳에 있다. 화면에서 직접 문자열을 쓰지 말고
거기서 가져다 써라. 두 화면이 같은 값을 다르게 부르면 같은 것인 줄 모른다.

명세의 뜻 문장(`CELL_MEANINGS` · `AXIS_POLES`)은 **명세 원문이라 고치지 마라.**
`prompts/reflect.md` 와 `soul-mcp` 가 같은 문장을 들고 있어서, 여기만 고치면
세 곳이 어긋난다.

### 10. `Explain` 은 접힌 채로 둔다

`components/Explain.tsx` 는 화면마다 하나씩 있는 "이게 무슨 뜻인가요" 다.
**기본은 닫힘이다.** 처음 온 사람은 접힌 줄 하나를 지나칠 뿐이고, 궁금해진
사람만 펼친다 — 대개 두세 번째 방문이고, 그때가 이 앱이 깊어지는 지점이다.

기본을 열림으로 바꾸거나, 접힌 줄을 본문만큼 눈에 띄게 만들지 마라.
설명하려던 화면을 설명이 덮는다.

툴팁으로 대신하지도 마라. 손가락으로 쓰는 화면에서는 뜨지 않고, 뜬다 해도
"여기 더 있다"는 사실 자체가 보이지 않는다.

### 11. `(§9.7)` 표시는 지우지 말고 밀어낸다

`.ref` (base.css) 로 감싸 작고 흐리게 둔다. 이 앱의 모든 동작에는 근거가
있고 그것을 확인할 수 있어야 하므로 **지우면 안 된다.** 다만 문장 한가운데
있으면 처음 온 사람에게는 뜻 없는 잡음이고, 잡음이 가운데 있으면 문장이
거기서 끊긴다. 그래서 문장 끝으로 민다.

### 12. 아카이브 200건 규칙

보이는 항목이 200건 이하면 썸네일 타일, 넘으면 단색 점이다.
수천 건에서 썸네일을 전부 그리면 첫 렌더 예산(500ms)을 넘긴다.

### 13. 프런트는 계산하지 않는다

축 값, 셀 판정, 군집, 필터는 전부 백엔드가 준 값을 그대로 그린다.
화면에서 다시 계산하지 마라 — 같은 값이 두 곳에서 달라진다.
`lib/api.ts` 에 없는 것은 프런트가 할 수 없는 일이다.

## 디자인 토큰

`styles/base.css` 상단의 CSS 변수가 토큰이다. 목록과 뜻은 [`TOKENS.md`](TOKENS.md).

라이트/다크 **양쪽 다** 대응해야 한다 (`prefers-color-scheme`).
지금은 다크가 기본이고 라이트는 덜 다듬어져 있다 — 좋은 작업거리다.

## 확인

```bash
npx tsc --noEmit     # 타입
npm run build        # 프로덕션 번들
```

백엔드 계약(`lib/api.ts` · `lib/types.ts`)은 Rust 쪽 `src-tauri/src/commands.rs` 의
거울이다. **여기 타입을 바꾸면 Rust 도 함께 바꿔야 한다.** 화면만 손볼 거라면
그 두 파일은 건드리지 않는 편이 안전하다.
