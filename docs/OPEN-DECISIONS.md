명세 머리말: *"명세에 없는 동작은 임의로 정하지 말고 추가한 뒤 질문할 것."*

전부 되돌릴 수 있는 선택이며, 코드에서 한 곳만 고치면 바뀌도록 배치했다.

## 구현 중 추가된 항목

### 14. 검색 제공자 — `[search] provider = "duckduckgo"`

§11.1은 `web_search(query) -> [{title,url,snippet}]`를 요구하지만 **누가 검색하는지 정하지 않았다.**
§D6은 "검색 제공자"라고만 쓴다. §9.8 설정 표에도 관련 키가 없다.

**둔 값**: `[search] provider = "duckduckgo"`, `api_key = ""`, `max_results = 8`.
`brave` · `tavily`도 구현하되 키가 필요하다.

**이유**: 키 없이 동작해야 최초 실행에서 문화 층이 죽지 않는다. 그리고 우리 함수로
검색해야 `context.queries`에 **실제로 나간 문자열**을 남길 수 있다 — 모델 호스팅
검색 툴을 쓰면 질의 문자열이 우리 손을 거치지 않아 §D6 고지의 근거가 무너진다.

**되돌리는 곳**: `crates/soul-net/src/search.rs`.

### 15. `soul mcp`는 별도 바이너리를 exec 한다

§2는 "MCP 서버 = 별도 바이너리, 네트워크 의존성 미링크"라 하고,
§14·§19.7은 `soul mcp`라는 서브커맨드를 요구한다. 둘 다 만족시키는 방법이 명시되지 않았다.

**둔 값**: `soul mcp`는 같은 디렉토리의 `soul-mcp` 실행 파일을 찾아 exec 한다
(unix `execv`, windows `spawn+wait`). `soul-mcp`의 의존성은 `soul-core`+`serde`뿐이다.

**이유**: `soul` 바이너리에는 `reqwest`가 링크되어 있으므로 거기서 서버를 돌리면
§19.4가 구조적으로 깨진다. exec 하면 서버 프로세스에 HTTP 클라이언트가 없다 (T32).

### 16. MCP 프로토콜을 직접 구현한다

**둔 값**: stdio JSON-RPC 2.0을 손으로 구현한다. MCP SDK를 의존성에 넣지 않는다.

**이유**: SDK를 넣으면 전이 의존으로 HTTP 클라이언트가 끌려들어올 수 있고,
그것이 §19.4를 조용히 깬다. 프로토콜 표면이 작아 직접 구현 비용이 낮다.

`protocolVersion`은 `2025-06-18`로 응답하되, 클라이언트가 다른 버전을 요청하면
그 값을 그대로 돌려준다.

### 17. `SOUL.md` 어긋남 블록의 `일관성`은 **sensory** 값이다

§8.2 템플릿은 `- 일관성 0.62 · 정정 18건` 한 줄인데,
§12.6은 `coherence`를 **layer별로 따로 계산한다**고 못박는다. 어느 쪽을 싣는지 미정.

**둔 값**: `일관성`은 `coherence_sensory.value`, `정정`은 **두 층 합쳐** `prose ≠ null`인
reading 수. 대표 사례도 sensory 쪽 것을 쓴다.
`query_stats`와 `soul://divergence`에는 **두 층 모두** 싣는다.

**이유**: 감각 층은 항상 존재하지만 문화 층은 `context_enabled = false`이거나 검색 실패로
비어 있을 수 있다. 헤더 한 줄에 없을 수도 있는 값을 넣으면 `—`가 자주 뜬다.

### 18. `SOUL.md` 헤더의 `관측 N`은 **활성 ingest 수**다

§8.2는 `관측 342`라고만 쓴다. 전체 관측 수인지 ingest 수인지 미정.

**둔 값**: supersede되지 않은 `ingest` 수 (§R9의 `|I|`).

**이유**: "무엇을 몇 개 투입했는가"가 사용자가 읽는 뜻이다. `reading`·`context`까지 합치면
투입 1건이 3~4로 세어져 숫자의 의미가 사라진다.

### 19. 정준 JSON은 파일 끝에 개행 하나를 붙인다

§R6은 "LF"라고만 하고 종료 개행을 말하지 않는다.

**둔 값**: 파일은 정확히 `}\n`으로 끝난다.

**이유**: POSIX 텍스트 파일 관례이며 git이 `\ No newline at end of file`를 붙이지 않는다.
T1은 자기 자신과의 비교이므로 어느 쪽이든 통과하지만, 일관성이 필요하다.

### 20. `min_dist` 캐시 군집은 `derived.sqlite`가 사라지면 재계산한다

§12.3의 캐시 규칙은 캐시가 존재할 때의 갱신 조건만 정한다.

**둔 값**: `cluster_cache`가 비면 다음 투입 때 전량 재계산한다 (`should_recluster(0, n) == true`).

**이유**: `min_dist`/`surprisal`은 이미 기록된 관측에서 동결되어 있으므로(§R4)
캐시 재생성이 과거 값에 영향을 주지 않는다.

### 21. ffmpeg 조달 URL과 해시는 설정 파일이 아니라 코드 상수다

§9.7은 "정적 빌드를 다운로드"라고만 한다.

**둔 값**: 플랫폼별 URL·SHA-256을 `soul-net::procure`에 상수로 둔다. 설정으로 노출하지 않는다.

**이유**: 사용자가 URL을 바꿀 수 있으면 SHA-256 검증(§9.7 단계 3)이 의미를 잃는다.

### 22. 감각 카드의 미응답분은 앱 메모리에만 있다

§13 화면 2가 "미응답 카드는 영속화하지 않는다"고 정했다. 어디에 두는지는 미정.

**둔 값**: Tauri 앱 상태(`AppState::sensory_cards`)에만 둔다. sqlite에 넣지 않는다.

**이유**: sqlite에 넣으면 "영속화하지 않는다"가 구현 세부에 따라 흔들린다.

### 23. `soul secrets` 서브커맨드를 추가했다 (§14에 없음)

§2는 키를 OS 키체인에 두라고 하지만, 넣는 **경로**를 정하지 않았다. 구현된 것은 Tauri
커맨드(`set_secret`)뿐이라 **GUI를 열어야만** 키를 넣을 수 있었다. 그러면 `scripts/setup.sh`가
환경을 끝까지 세팅할 수 없고, 헤드리스 CI도 막힌다.

**둔 값**: `soul secrets set|status|delete|import-env`.
- 값은 **stdin으로만** 받는다 — 인자로 받으면 셸 히스토리와 `ps`에 키가 남는다.
- `status`는 **설정 여부만** 출력한다. 값도, 앞자리 몇 글자도 출력하지 않는다.
- `import-env`는 빈 환경변수를 건너뛴다 — `.env.example`을 그대로 복사한 상태에서
  빈 키가 저장되어 "설정됨"으로 보이는 것이 가장 나쁘다.

### 24. `.env`는 키 저장소가 아니라 **투입구**다

§2는 키체인을 지정하지만, 개발자가 키를 어디에 적어 두는지는 정하지 않았다.

**둔 값**: `.env`(gitignore)는 `scripts/setup.sh`가 읽어 **키체인으로 옮기는** 대상이며,
앱 런타임은 `.env`를 읽지 않는다. 옮긴 뒤 파일은 지워도 된다.

**이유**: 키 저장소를 둘 두면 어느 쪽이 진실인지 알 수 없게 되고, 평문 파일 쪽이
조용히 이긴다. §2의 요지는 "키체인에 둔다"가 아니라 "키가 평문으로 굴러다니지 않는다"이다.

### 25. `SOUL_ALLOW_ENV_SECRETS` — 기본 꺼짐인 환경변수 폴백

헤드리스 CI(Secret Service 없음)에서 `SOUL_E2E` 테스트를 돌릴 방법이 필요하다.

**둔 값**: `SOUL_ALLOW_ENV_SECRETS=1`일 때만 `secrets::get`이 키체인 **다음에**
환경변수를 본다. 기본값은 꺼짐. 폴백이 실제로 쓰이면 stderr로 한 번 경고한다.

**순서가 중요하다 — 키체인이 먼저다.** 반대로 두면 셸에 남은 오래된 `OPENAI_API_KEY`
하나가 사용자가 설정 화면에서 넣은 키를 조용히 덮어쓰고, "왜 예전 키로 호출되지?"를
디버깅할 방법이 없다. 이 순서를 테스트로 못박았다
(`soul-net/src/secrets.rs::env_fallback_tests`).

## 스모크 테스트로 찾은 것

`.gitattributes`·`.gitignore`가 **커밋되지 않고 있었다.** `App::open_or_init`은 커밋했지만
`soul render`처럼 그것을 거치지 않는 진입점이 있어서, **어느 명령을 먼저 실행했느냐로
저장소 상태가 갈렸다.** `.gitattributes`의 `*.md text eol=lf`가 커밋되어 있지 않으면
새 체크아웃(백업 복원·과거 조회)에서 규칙이 적용되지 않아 Windows에서 CRLF가 되고
§8.3의 해시 정규화가 다른 바이트를 본다 — T1이 깨진다.
→ `git::ensure_repo`가 직접 커밋하도록 옮겼다. 어느 진입점을 쓰든 같은 상태가 된다.

## 남은 것 (구현되지 않았거나 확인이 필요한 것)

### A. §20.7 "대시보드 열기 = 읽기만"이 아직 성립하지 않는다

`db::derived_cache`의 `month_state_get`/`month_state_put`을 **읽거나 쓰는 코드가 없다.**
`ingest`가 `month_state_invalidate`만 부르고, `derived::state::timeline`은 `Db`를 받지 않아
매번 전량 계산한다. 따라서 대시보드를 열 때마다 관측 전체가 재생된다.

**영향**: T39(관측 5,000건에서 첫 렌더 < 500ms)가 위태롭다. 실측하지 않았다.
**필요한 변경**: `derived::state::timeline`이 `Db`를 받아 지난 달은 캐시에서 읽게 한다.
캐시 무효화 규칙(§12.5 — 관측이 추가된 달 하나만)은 이미 구현되어 있다.

### B. `App`이 `Sync`가 아니다

`soul_core::db::Db`가 `rusqlite::Connection`을 그대로 들고 있어 `App: !Sync`다.
Tauri v2는 커맨드 future가 `Send`여야 하므로, 모든 커맨드가
`state::run_pipeline`(`block_in_place`) 또는 전용 스레드를 거친다. 동작에는 문제가 없다.
`Connection`을 `Mutex`로 감싸면 그 우회 계층이 통째로 사라진다.

### C. ffmpeg 조달 해시가 비어 있다

§9.7은 SHA-256 검증을 요구하지만 명세가 URL과 해시를 주지 않는다.
**해시를 지어내지 않았다.** `procure::download_verified`는 해시가 비어 있으면
다운로드를 **거부하고** "ffmpeg을 직접 설치해 주세요"라고 알린다.
검증 없이 실행 파일을 내려받는 것보다 낫다고 판단했다. 배포 전에 실제 값을 채워야 한다.

### D. 네트워크가 필요한 경로는 실사용으로 확인하지 않았다

API 키가 없어 OpenAI·YouTube·검색 호출은 목 서버로만 검증했다.
`#[ignore]` + `SOUL_E2E=1`로 게이트된 테스트 13건이 그 경로를 덮는다.
M1~M9의 체크포인트(§16)는 실제 키로 한 번 돌려 봐야 완료 판정이 선다.
